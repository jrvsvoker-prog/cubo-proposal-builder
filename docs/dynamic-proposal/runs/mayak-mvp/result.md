## Что задано

Вымышленный сервис обслуживает кофемашины в офисах: одна услуга за 6 500 ₽,
подразделений нет, primary #0f766e. Участники, очередь заказов и даты —
демонстрационные допущения. Источника с реальными данными компании нет.
Путь сборки разрешён пользователем; повторного подтверждения вымышленной
сводки для этого авторского примера не требовалось.

## Как воспроизвести

Из `app-cubo-showcase/`:

```bash
node scripts/profile-draft.mjs docs/dynamic-proposal/runs/mayak-mvp/summary.json
npm run build:all
npm run build -- --mode mayak-mvp --outDir dist/mayak-mvp
```

Профиль зарегистрирован в `profiles.typecheck.ts`. Он полностью выдан скриптом,
без ручного изменения готового JSON. Повтор через `--out` дал побайтно тот же
профиль. Во время сверки исправлена только поясняющая строка `assumptions`
в сводке о неиспользуемом monthlyDeals, затем профиль и HTML пересобраны.
Хеши окончательных файлов — [verification.json](verification.json).

## Что показал прогон

**Полную согласованность данных пока не принимать.**

1. Единственная услуга стоит 6 500 ₽, но исходный дашборд показывает 259
   выполненных заказов и выручку 4,9 млн ₽. KPI строятся моделью архетипа
   независимо от прайса и масштаба сводки. Это не данные этого вымышленного
   бизнеса, рассчитанные по его цене. Ограничение внесено в регламент.
2. Для четвёртой стадии задано «Выполнено», а кабинет одновременно показывает
   «Этап 1 из 3 — работа начата». Скрипт переносит подпись стадии, но текст
   прогресса жёстко задан. Это конкретная несогласованность для исправления
   перед приёмкой полного процесса.

Эти места не исправлялись вручную в профиле и не скрывались изменением входа.
Регламент, обработка логотипа, независимый прогон и итоговая выдача сохраняют
свои отдельные критерии. Обложка/финал приняты для MVP; пробные шапки глав без
подложки ожидают визуальной приёмки.
